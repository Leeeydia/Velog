<p>팀 프로젝트 전에 Git을 제대로 연습해보고 싶어서<br />이번 개인 프로젝트에서는 브랜치를 나눠서 개발해보기로 했다.</p>
<hr />
<h2 id="📂-브랜치-전략">📂 브랜치 전략</h2>
<h3 id="🔹-main">🔹 main</h3>
<ul>
<li>기본 개발 환경 세팅만 유지</li>
<li>항상 안정 상태</li>
<li>배포 기준 브랜치</li>
</ul>
<h3 id="🔹-dev">🔹 dev</h3>
<ul>
<li>개발 통합 브랜치</li>
<li>기능 브랜치들이 머지되는 공간</li>
</ul>
<h3 id="🔹-feat">🔹 feat/*</h3>
<ul>
<li>기능 단위 개발 브랜치</li>
<li>예: feat/login, feat/diary-list, feat/ai-reply</li>
</ul>
<hr />
<h2 id="🔄-개발-흐름">🔄 개발 흐름</h2>
<pre><code>main  →  기본 세팅
  ↓
dev   →  기능 통합
  ↓
feat/* → 기능 단위 작업</code></pre><hr />
<h1 id="🛠-자주-사용하는-git-명령어-정리">🛠 자주 사용하는 Git 명령어 정리</h1>
<h2 id="1️⃣-dev-브랜치로-이동">1️⃣ dev 브랜치로 이동</h2>
<pre><code class="language-bash">git checkout dev</code></pre>
<hr />
<h2 id="2️⃣-원격-dev-최신-코드-가져오기">2️⃣ 원격 dev 최신 코드 가져오기</h2>
<pre><code class="language-bash">git pull origin dev</code></pre>
<p>👉 다른 작업이 있을 수 있으므로 항상 최신 상태 유지</p>
<hr />
<h2 id="3️⃣-기능-브랜치-생성-및-이동">3️⃣ 기능 브랜치 생성 및 이동</h2>
<pre><code class="language-bash">git checkout -b feat/diary-list</code></pre>
<ul>
<li><code>-b</code> : 브랜치 생성 + 이동</li>
<li>기능 단위로 브랜치 생성</li>
</ul>
<hr />
<h2 id="🔎-⚠️-브랜치-생성-시-주의할-점">🔎 ⚠️ 브랜치 생성 시 주의할 점</h2>
<p>기능 브랜치는 <strong>현재 위치한 브랜치를 기준으로 생성</strong>된다.</p>
<p>즉, 반드시 기준 브랜치(dev)로 먼저 이동한 뒤 생성해야 한다.</p>
<pre><code class="language-bash">git checkout dev
git pull origin dev
git checkout -b feat/diary-list</code></pre>
<p>만약 main 상태에서 <code>-b</code>를 실행하면<br />main에서 파생된 브랜치가 만들어지므로 의도와 달라질 수 있다.</p>
<hr />
<h2 id="4️⃣-변경-파일-확인">4️⃣ 변경 파일 확인</h2>
<pre><code class="language-bash">git status</code></pre>
<p>👉 현재 브랜치 / 변경된 파일 확인</p>
<hr />
<h2 id="5️⃣-변경-파일-스테이징">5️⃣ 변경 파일 스테이징</h2>
<pre><code class="language-bash">git add .</code></pre>
<p>👉 전체 파일 추가<br />(특정 파일만 추가할 경우 <code>git add 파일명</code>)</p>
<hr />
<h2 id="6️⃣-커밋">6️⃣ 커밋</h2>
<pre><code class="language-bash">git commit -m &quot;feat: 로그인 사용자 일기 목록 조회 API 구현&quot;</code></pre>
<p>✔ 커밋 메시지는 작업 단위가 명확하게 작성</p>
<hr />
<h2 id="7️⃣-원격-저장소로-푸시">7️⃣ 원격 저장소로 푸시</h2>
<pre><code class="language-bash">git push -u origin feat/diary-list</code></pre>
<ul>
<li><code>-u</code> 옵션을 사용하면</li>
<li>이후부터는 <code>git push</code>만 입력해도 됨</li>
</ul>
<hr />
<h1 id="📌-기능-완료-후-흐름">📌 기능 완료 후 흐름</h1>
<ol>
<li>GitHub에서 PR 생성</li>
<li>base: dev</li>
<li>dev 브랜치로 merge</li>
<li>기능 충분히 안정화되면 dev → main merge</li>
</ol>
<hr />
<h1 id="💡-느낀-점">💡 느낀 점</h1>
<p>개인 프로젝트라도 브랜치를 나눠서 관리하면<br />작업 단위가 명확해지고<br />실제 팀 프로젝트와 동일한 환경을 연습할 수 있다.</p>
<p>Git은 많이 써볼수록 익숙해지는 도구라<br />개인 프로젝트에서 적극적으로 연습해보는 것이 좋다고 느꼈다.</p>
