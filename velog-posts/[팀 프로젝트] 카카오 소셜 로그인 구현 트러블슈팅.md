<h2 id="문제-1-redirect-uri-미등록으로-인한-401-오류">문제 1. Redirect URI 미등록으로 인한 401 오류</h2>
<h3 id="증상">증상</h3>
<pre><code>401 Unauthorized from POST https://kauth.kakao.com/oauth/token</code></pre><h3 id="원인">원인</h3>
<p>카카오 OAuth는 토큰 요청 시 <code>redirect_uri</code> 값이 카카오 콘솔에 사전 등록된 URI와 정확히 일치하는지 검증합니다. 코드에는 올바르게 설정되어 있었지만 카카오 콘솔에 등록하지 않아서 401이 발생했습니다.</p>
<h3 id="해결">해결</h3>
<p>카카오 Developers 콘솔에서 Redirect URI를 등록합니다.</p>
<pre><code>카카오 콘솔 → 카카오 로그인 → 일반 → Redirect URI 추가
http://localhost:5173/auth/kakao/callback</code></pre><h3 id="교훈">교훈</h3>
<p>카카오 OAuth 연동 시 코드 작성 전에 콘솔 설정을 먼저 완료해야 합니다. Redirect URI는 프론트에서 카카오 인가 URL 생성 시 사용하는 값과 콘솔에 등록된 값이 완전히 동일해야 하며, 오타나 슬래시 유무 차이도 인증 실패 원인이 됩니다.</p>
<hr />
<h2 id="문제-2-intellij-환경변수-미주입으로-인한-설정값-누락">문제 2. IntelliJ 환경변수 미주입으로 인한 설정값 누락</h2>
<h3 id="증상-1">증상</h3>
<p><code>application.yml</code>에 환경변수 플레이스홀더로 설정하고 IntelliJ Run Configuration에 값을 입력했지만 간헐적으로 설정값이 주입되지 않아 요청이 실패했습니다.</p>
<pre><code class="language-yaml">kakao:
  client-id: ${KAKAO_CLIENT_ID}
  redirect-uri: ${KAKAO_REDIRECT_URI}</code></pre>
<h3 id="원인-1">원인</h3>
<p>IntelliJ Run Configuration 환경변수는 빌드 방식이나 실행 프로파일에 따라 적용이 누락될 수 있습니다. 특히 Gradle 빌드와 Spring Boot 플러그인 실행이 혼용될 때 환경변수가 전달되지 않는 경우가 있습니다.</p>
<h3 id="해결-1">해결</h3>
<p>Spring Boot 프로파일 분리 방식을 적용합니다.</p>
<p><strong>1. <code>application.yml</code>에 secret 프로파일 포함 설정</strong></p>
<pre><code class="language-yaml">spring:
  profiles:
    include: secret</code></pre>
<p><strong>2. <code>application-secret.yml</code> 생성</strong></p>
<pre><code class="language-yaml">kakao:
  client-id: 실제_REST_API_키
  redirect-uri: http://localhost:5173/auth/kakao/callback</code></pre>
<p><strong>3. <code>.gitignore</code>에 등록</strong></p>
<pre><code>/src/main/resources/application-secret.yml</code></pre><h3 id="교훈-1">교훈</h3>
<p>개발 환경의 민감 정보는 IDE 환경변수보다 Spring 프로파일 기반 파일 분리 방식이 더 안정적입니다. <code>application-secret.yml</code>은 반드시 <code>.gitignore</code>에 포함하고, 팀원에게 로컬 생성 방법을 별도로 공유해야 합니다.</p>
<hr />
<h2 id="문제-3-클라이언트-시크릿-활성화로-인한-지속적-401-오류">문제 3. 클라이언트 시크릿 활성화로 인한 지속적 401 오류</h2>
<h3 id="증상-2">증상</h3>
<p>Redirect URI 등록 후에도 동일한 401 오류가 계속 발생했습니다. 로그에서 REST API 키와 Redirect URI가 정상 주입되고 있음을 확인했지만 인증은 계속 실패했습니다.</p>
<pre><code>kakaoClientId: 3f1e50e1ec6fcc...
kakaoRedirectUri: http://localhost:5173/auth/kakao/callback
401 Unauthorized from POST https://kauth.kakao.com/oauth/token</code></pre><h3 id="원인-2">원인</h3>
<p>카카오 Developers 콘솔에서 REST API 키 발급 시 <strong>클라이언트 시크릿이 기본으로 활성화</strong>됩니다. 클라이언트 시크릿이 활성화된 상태에서는 토큰 요청 시 <code>client_secret</code> 파라미터를 반드시 함께 전송해야 합니다. 코드에서는 해당 파라미터 없이 요청하고 있었습니다.</p>
<h3 id="해결-2">해결</h3>
<p><strong>방법 A (권장): 클라이언트 시크릿 비활성화</strong></p>
<pre><code>카카오 콘솔 → 앱 설정 → 플랫폼 키 → REST API 키 수정
→ 클라이언트 시크릿 → 비활성화 → 저장</code></pre><p><strong>방법 B: 코드에 client_secret 파라미터 추가</strong></p>
<pre><code class="language-java">params.add(&quot;client_secret&quot;, kakaoClientSecret);</code></pre>
<h3 id="교훈-2">교훈</h3>
<p>카카오 REST API 키 발급 후에는 콘솔의 보안 설정을 반드시 확인해야 합니다. 클라이언트 시크릿은 보안 강화 목적으로 기본 활성화되어 있으며, 이를 인지하지 못하면 코드와 설정이 모두 올바른 상황에서도 인증이 실패합니다.</p>
<hr />
<h2 id="문제-4-db-스키마-미적용으로-인한-컬럼-누락">문제 4. DB 스키마 미적용으로 인한 컬럼 누락</h2>
<h3 id="증상-3">증상</h3>
<p>카카오 토큰 발급 성공 후 사용자 조회 단계에서 오류가 발생했습니다.</p>
<pre><code>오류: u1_0.kakao_id 칼럼 없음
JDBC exception executing SQL [select u1_0.user_id, ..., u1_0.kakao_id, ...]</code></pre><h3 id="원인-3">원인</h3>
<p><code>User</code> 엔티티에 <code>kakao_id</code>와 <code>provider</code> 필드를 추가했지만 실제 DB의 <code>users</code> 테이블에는 해당 컬럼이 없었습니다. 프로젝트에서 <code>spring.jpa.hibernate.ddl-auto: none</code> 설정을 사용하고 있어 엔티티 변경이 DB에 자동 반영되지 않습니다.</p>
<h3 id="해결-3">해결</h3>
<p>PostgreSQL에서 직접 DDL을 실행합니다.</p>
<pre><code class="language-sql">ALTER TABLE users ADD COLUMN kakao_id VARCHAR(255);
ALTER TABLE users ADD COLUMN provider VARCHAR(50);</code></pre>
<h3 id="교훈-3">교훈</h3>
<p><code>ddl-auto: none</code> 환경에서는 엔티티 변경 시 DB 스키마도 함께 변경해야 합니다. 팀 협업 시 엔티티 변경을 포함한 PR에는 DB 마이그레이션 스크립트를 반드시 포함해야 합니다. 향후 Flyway나 Liquibase 도입을 고려하면 좋습니다.</p>

<h2 id="문제-5-not-null-제약-조건-위반으로-인한-신규-회원-저장-실패">문제 5. NOT NULL 제약 조건 위반으로 인한 신규 회원 저장 실패</h2>
<h3 id="증상-4">증상</h3>
<p>카카오 토큰 발급과 이메일 조회까지 성공했지만 신규 회원 저장 단계에서 오류가 발생했습니다.</p>
<pre><code>오류: &quot;name&quot; 칼럼(해당 릴레이션 &quot;users&quot;)의 null 값이
not null 제약조건을 위반했습니다.
Detail: 실패한 자료: (..., fleldk7@naver.com, , fleldk7, null, null, ...)</code></pre><h3 id="원인-4">원인</h3>
<p>카카오 로그인으로 신규 가입하는 사용자는 이름(<code>name</code>)과 전화번호(<code>phone</code>)를 입력하지 않습니다. 카카오 API로부터는 이메일만 수신하여 사용자를 생성하는데, 기존 <code>users</code> 테이블의 <code>name</code>과 <code>phone</code> 컬럼이 <code>NOT NULL</code> 제약 조건으로 설정되어 있어 충돌이 발생했습니다.</p>
<h3 id="해결-4">해결</h3>
<pre><code class="language-sql">ALTER TABLE users ALTER COLUMN name DROP NOT NULL;
ALTER TABLE users ALTER COLUMN phone DROP NOT NULL;</code></pre>
<h3 id="교훈-4">교훈</h3>
<p>소셜 로그인 기능 추가 시 기존 DB 스키마의 제약 조건을 함께 검토해야 합니다. 일반 회원가입과 소셜 로그인은 수집하는 사용자 정보의 범위가 다르기 때문에, 소셜 로그인 도입 시점에 필수/선택 필드를 재정의하고 스키마에 반영해야 합니다.</p>
