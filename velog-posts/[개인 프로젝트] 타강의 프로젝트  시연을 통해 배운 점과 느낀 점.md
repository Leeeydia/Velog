<p>이번에 다른 강의 팀들의 발표를 들으면서
내가 미처 생각하지 못했던 기능들과 고려해야 할 포인트들을 많이 알게 되었다.
이번 글에서는 그중 인상 깊었던 기술들과,
시간이 된다면 내 프로젝트에도 추가로 구현해보고 싶은 기능들,
그리고 DB 관련해서 새로 알게 된 중요한 개념을 정리해보려고 한다.</p>
<h2 id="1️⃣-i18n-다국어-처리--자동-번역-기능">1️⃣ i18n (다국어 처리) &amp; 자동 번역 기능</h2>
<p>발표를 들으면서 처음 알게된 개념이었다</p>
<h4 id="✔-i18n이란">✔ i18n이란?</h4>
<p>하나의 서비스에서 여러 언어를 지원할 수 있도록 구조를 미리 설계하는 것</p>
<p>화면에 직접 한글/영문을 박아두는 게 아니라
→ 언어별 메시지 파일을 분리해서 관리</p>
<p>같은 텍스트를 언어 설정에 따라 자동으로 바꿔주는 방식이다.</p>
<h4 id="✔-자동-번역-기능">✔ 자동 번역 기능</h4>
<p>번역 API를 활용해서 게시글, 댓글, 안내 문구 등을 사용자 언어에 맞게 자동 번역 할 수 있다.</p>
<p>요즘 시대에 실제 웹페이지를 만들어야 한다면 필수로 구현해야하는 서비스가 아닐까? 라는 생각이 들었다.
하지만 아직 개발을 공부하는 단계에서는 기본 mvp를 넘어선 기능이지 않을까 라는 생각이 들어서 개인 프로젝트 기간 이후 시간이 된다면 글로벌 서비스로 디벨롭 해보고싶다는 생각이 들었다.</p>
<h2 id="2️⃣-챗봇-ai-활용">2️⃣ 챗봇 AI 활용</h2>
<p>AI 챗봇을 단순히 고객센터와의 &quot;대화용&quot; 으로만 생각했는데 발표를 들으면서 활용 범위가 훨씬 넓다는 걸 알게 되었다.</p>
<h4 id="✔-활용-예시">✔ 활용 예시</h4>
<ul>
<li>FAQ 자동 응답</li>
<li>게시판 이용 방법 안내</li>
<li>서비스 기능 설명</li>
<li>간단한 검색 보조</li>
</ul>
<p>이러한 방식은 특히 초기 서비스에서 관리자가 직접 대응하지 않아도 된다는 점에서
운영 부담을 크게 줄일 수 있을 것 같다는 생각이 들었다.</p>
<p>이번 일기장 프로젝트에 적극적으로 반영해야겠다 !</p>
<h2 id="3️⃣-소셜-로그인-oauth">3️⃣ 소셜 로그인 (OAuth)</h2>
<p>소셜 로그인을 시도 해볼까 말까 고민했는데, 역시 많은 회원가입을 위해서라면
꼭 필요할 것 같았다.</p>
<p>회원가입 + 로그인 과정을 단순화 한다는 점이 ux/ui적으로 굉장히 메리트가 있는 거 같다</p>
<h2 id="4️⃣-임시-저장-기능-draft">4️⃣ 임시 저장 기능 (Draft)</h2>
<p>블로그로 일기를 작성하면서 수십번 임시저장을 하는데
그럼에도 불구하고 까먹고 있었던 기능! </p>
<p>이번 발표를 통해서 다시 한 번 상기 시킬 수 있었다.. 휴</p>
<h4 id="✔-임시-저장이-왜-필요할까">✔ 임시 저장이 왜 필요할까?</h4>
<ul>
<li>글 작성 중 새로고침</li>
<li>뒤로 가기</li>
<li>브라우저 종료
→ 작성 내용 전부 날아가는 문제 발생</li>
</ul>
<p>임시 저장 기능이 있으면 일정 시간마다 자동 저장하거나, 사용자가 직접 임시 저장 클릭
해서 나중에 이어서 작성 가능하게 구현해봐야겠다.</p>
<h2 id="5️⃣-db에-데이터가-많이-쌓이면-터질-수-있다는-사실">5️⃣ DB에 데이터가 많이 쌓이면 터질 수 있다는 사실</h2>
<p>역시 프론트가 더 재밌어요 백엔드 바보는 이런 부분까진 생각하지도 못한...
지금까지의 내 생각으론 DB에 그냥 다 쌓으면 되는 거 아닌가? 했는데 발표 이후 다시 한 번 더 생각해보니 비용문제 등등 뭔가 많은 문제가 있을 거 같다는 생각이 들었다.</p>
<h4 id="✔-데이터가-많아질수록">✔ 데이터가 많아질수록</h4>
<ul>
<li><p>조회 속도 느려짐</p>
</li>
<li><p>서버 부하 증가</p>
</li>
<li><p>쿼리 성능 저하</p>
</li>
</ul>
<p>-&gt; 잘못하면 서비스가 터질 수도 있음</p>

</li>
