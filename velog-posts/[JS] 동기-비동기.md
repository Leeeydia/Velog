<h3 id="동기">동기</h3>
<ul>
<li>코드는 위에서 아래로 한 줄씩 순서대로 실행된다.</li>
<li>앞의 작업이 완전히 끝나야 다음 작업이 실행된다.</li>
<li>하나의 작업이 오래 걸리면, 그 다음 작업은 그동안 멈춰있는다.</li>
</ul>
<h3 id="비동기">비동기</h3>
<ul>
<li>작업 완료를 기다리지 않고 다음 작업을 먼저 실행한다.</li>
<li>시간이 오래 걸리는 작업은 다른 곳에 맡기고, 작업이 끝나면 &quot;이제 끝났어&quot; 라고 말해주면 그때 일을 처리한다</li>
<li>완료 시점에 콜백/Promise/async-await로 결과를 처리한다.</li>
</ul>
<h3 id="왜-비동기가-중요한가-">왜 비동기가 중요한가 ?</h3>
<ol>
<li>대규모 트래픽에도 안정적인 서비스를 제공할 수 있다.</li>
</ol>
<ul>
<li>한 요청 때문에 서버가 멈추지 않는다</li>
</ul>
<ol start="2">
<li>지원 효율이 좋다</li>
</ol>
<ul>
<li>CPI, 스레드를 불필요하게 잡고있지 않는다</li>
</ul>
<ol start="3">
<li>응답 속도 개선에 도움이 된다</li>
</ol>
<ul>
<li>동시에 여러 작업을 처리할 수 있다.</li>
</ul>
<h3 id="내-생각">내 생각</h3>
<ul>
<li>서버는 한 명만 쓰는게 아니라 여러 사용자가 동시에 요청을 보내기 때문에
하나 기다린다고 다 멈추는 구조는 현실적으로 말이 안된다 느꼈고,
비동기의 중요성에 대해 다시 한번 공부하는 계기가 되었다.</li>
</ul>
