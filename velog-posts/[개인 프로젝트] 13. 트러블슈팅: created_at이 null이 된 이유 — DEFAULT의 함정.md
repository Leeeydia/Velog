<h3 id="🧨-문제-상황">🧨 문제 상황</h3>
<p>일기 작성 API는 정상적으로 동작했고, 응답도 잘 내려왔다.<br />하지만 DB를 직접 조회해보니 <code>created_at</code> 컬럼이 <code>null</code>로 저장되어 있었다.</p>
<p>테이블에는 다음과 같이 설정되어 있었다.</p>
<pre><code class="language-sql">created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP</code></pre>
<p>분명히 <code>DEFAULT CURRENT_TIMESTAMP</code>가 설정되어 있었는데도 시간이 자동으로 들어가지 않았다.</p>
<hr />
<h4 id="🔍-원인-분석">🔍 원인 분석</h4>
<p>문제는 <strong>insert 쿼리에서 <code>created_at</code>에 null을 명시적으로 전달한 것</strong>이었다.</p>
<p>예시:</p>
<pre><code class="language-sql">INSERT INTO diary (member_id, content, emotion, created_at)
VALUES (1, '오늘은 피곤했다.', 'TIRED', null);</code></pre>
<p>여기서 중요한 포인트는 다음이다.</p>
<ul>
<li>MySQL에서 <code>DEFAULT</code> 값은 <strong>컬럼이 아예 생략되었을 때만 동작한다</strong></li>
<li><code>null</code>은 “값이 없음”이 아니라 <strong>“null이라는 값”</strong></li>
</ul>
<p>즉,</p>
<ul>
<li>❌ <code>created_at = null</code> → DB는 null을 그대로 저장</li>
<li>⭕ <code>created_at</code> 컬럼 자체를 생략 → DEFAULT CURRENT_TIMESTAMP 동작</li>
</ul>
<p>이 차이 때문에 시간이 자동으로 저장되지 않았던 것이다.</p>
<hr />
<h4 id="🛠-해결-방법">🛠 해결 방법</h4>
<p>insert 쿼리에서 <code>created_at</code> 컬럼을 제거했다.</p>
<pre><code class="language-sql">INSERT INTO diary (member_id, content, emotion)
VALUES (1, '오늘은 피곤했다.', 'TIRED');</code></pre>
<p>이렇게 수정하자 DB가 자동으로 현재 시간을 세팅했다.</p>
<p>애플리케이션에서 시간을 세팅하지 않고,<br />시간 책임을 DB에 위임하는 방식으로 정리했다.</p>
<hr />
<h4 id="📚-배운-점">📚 배운 점</h4>
<ol>
<li><code>DEFAULT</code>는 컬럼이 생략될 때만 동작한다.</li>
<li><code>null</code>은 값이 없는 것이 아니라, <strong>null이라는 값</strong>이다.</li>
<li>자동 시간 컬럼은 애플리케이션이 아니라 DB가 관리하는 것이 더 안전하다.</li>
<li>insert 쿼리를 작성할 때 불필요한 컬럼을 포함하지 않는 것이 중요하다.</li>
</ol>
