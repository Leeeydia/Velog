<h3 id="http-hypertext-transfer-protocol">HTTP (Hypertext Transfer Protocol)</h3>
<p>웹에서 클라이언트와 서버 간 통신을 위한 통신 규약입니다.
HTTP는 암호화되지 않는 평문 데이터를 전송하기 때문에 제 3자가 정보를 조회할 수 있다는 위험이 있습니다</p>
<h3 id="https">HTTPS</h3>
<p>HTTP의 보안 문제를 보완하기 위해 등장했습니다.
기존에 있던 HTTP에 데이터 암호화가 추가되었으며
암호회 된 데이터를 전송하기 때문에 제 3자가 볼 수 없습니다.</p>
<h3 id="https-적용-법">HTTPS 적용 법</h3>
<p>인증된 기관 (CA) 에게 인증서를 발급받아야합니다.
CA에 인증서를 요청하면 CA는 이름, 서버의 공개키, 서버의 정보를 활용하여 인증서를 생성하고
이를 CA 개인 키로 암호화하여 서버로 전송합니다.</p>
<h3 id="https-동작원리">HTTPS 동작원리</h3>
<p>클라이언트가 서버로 최로로 요청할 때 암호화 알고리즘, 프로토콜 버전, 무작위 값을 전달합니다.
이를 받은 서버는 클라이언트에게 받은 값들을 전달하고, 클라이언트는 서버의 인증서를 CA의 공개키로 복호화하여 검증합니다.</p>
<p>검증이 끝난 이후에는 클라이언트와 서버에서 생성된 무작위 값을 조합하여 Pre Master Secret 값을 생성하여 서버 고액키로 암호화하여 전달합니다.</p>
<p>클라이언트와 서버는 일련의 과정을 통해 Pre Master Secret를 Master Secret으로 변경하고, 해당 정보를 이용해 세션 키를 생성합니다.</p>
<p>이러한 과정을 TLS 핸드쉐이크 라고하며 이후부터 클라이언트와 서버는 세션 키를 활용한 대칭키 암호화 방식으로 데이터를 송수신 합니다.</p>
