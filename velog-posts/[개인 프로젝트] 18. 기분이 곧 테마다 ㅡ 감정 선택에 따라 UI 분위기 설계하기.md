<p>메인 화면에서 사용자가 감정 카드를 선택하면<br />해당 감정에 맞는 분위기의 일기 작성 화면으로 이동하도록 구현했다.</p>
<p><img alt="" src="https://velog.velcdn.com/images/leeeydia/post/234f47d2-7d5d-4746-86ed-81a01301828f/image.png" />
<em>(카드 색상/이미지 적용 전)</em></p>
<p>단순한 라우팅이 아니라,<br />선택한 감정 데이터를 기반으로<br />UI 분위기를 동적으로 변경하는 구조다.</p>
<hr />
<h3 id="1️⃣-구현-목표">1️⃣ 구현 목표</h3>
<ul>
<li>메인 화면에서 감정 카드 4개 표시</li>
<li>카드 클릭 시 일기 작성 페이지로 이동</li>
<li>선택한 감정에 따라 배경색/분위기 변경</li>
</ul>
<p>즉,</p>
<pre><code>감정 선택 → 감정 값 전달 → 해당 감정에 맞는 UI 렌더링</code></pre><hr />
<h3 id="2️⃣-감정-타입-정의-백엔드와-일치">2️⃣ 감정 타입 정의 (백엔드와 일치)</h3>
<p>백엔드 Emotion enum과 동일하게 타입을 맞췄다.</p>
<pre><code class="language-ts">export type Emotion =
  | &quot;HAPPY&quot;
  | &quot;SAD&quot;
  | &quot;ANGRY&quot;
  | &quot;CALM&quot;;</code></pre>
<p>카드를 클릭하면 감정 값을 쿼리 파라미터로 전달한다.</p>
<pre><code class="language-ts">navigate(`/write?emotion=${emotion}`);</code></pre>
<p>URL 예시:</p>
<pre><code>/write?emotion=CALM</code></pre><hr />
<h3 id="3️⃣-usesearchparams로-감정-값-읽기">3️⃣ useSearchParams로 감정 값 읽기</h3>
<p>일기 작성 페이지에서 쿼리 파라미터를 읽는다.</p>
<pre><code class="language-ts">const [searchParams] = useSearchParams();
const emotion = searchParams.get(&quot;emotion&quot;) as Emotion;</code></pre>
<p>이제 현재 선택된 감정에 따라 UI를 분기할 수 있다.</p>
<hr />
<h2 id="4️⃣-감정에-따른-스타일-설계">4️⃣ 감정에 따른 스타일 설계</h2>
<p>조건문 대신 객체 매핑 방식을 사용했다.</p>
<pre><code class="language-ts">const emotionStyle: Record&lt;Emotion, string&gt; = {
  HAPPY: &quot;bg-yellow-100&quot;,
  SAD: &quot;bg-blue-100&quot;,
  ANGRY: &quot;bg-red-200&quot;,
  CALM: &quot;bg-green-100&quot;,
};</code></pre>
<pre><code class="language-tsx">&lt;div className={`min-h-screen ${emotionStyle[emotion]}`}&gt;</code></pre>
<p>감정이 추가되면 객체에만 추가하면 되므로<br />확장에도 유리한 구조다.</p>
<hr />
<h2 id="5️⃣-왜-상태가-아니라-url로-전달했을까">5️⃣ 왜 상태가 아니라 URL로 전달했을까?</h2>
<p>감정을 React state로 넘길 수도 있었지만,<br />URL에 감정 정보가 남도록 설계했다.</p>
<p>이렇게 하면:</p>
<ul>
<li>새로고침해도 감정 유지</li>
<li>URL 공유 가능</li>
<li>디버깅이 쉬움</li>
<li>페이지 진입 경로가 명확함</li>
</ul>
<p>데이터 흐름 관점에서 URL이 더 적절하다고 판단했다.</p>
<hr />
<h3 id="🎨-감정-디자인은-어떻게-결정했을까-색채-심리학-참고">🎨 감정 디자인은 어떻게 결정했을까? (색채 심리학 참고)</h3>
<p>감정에 따른 배경색을 단순히 “예쁜 색”으로 정하고 싶지는 않았다.<br />사용자가 선택한 감정과 시각적 분위기가 어느 정도 연결되길 원했다.</p>
<p>그래서 색채 심리학(Color Psychology)과<br />감정-색 연관성에 대한 연구 자료를 참고했다.</p>
<p>색은 문화적 차이가 존재하지만,<br />여러 연구에서 반복적으로 나타나는 경향성이 있다.</p>
<hr />
<h4 id="✔-happy-→-밝고-부드러운-노란-톤">✔ HAPPY → 밝고 부드러운 노란 톤</h4>
<p>노란색은 긍정, 활력, 낙관과 연관되는 색으로 자주 언급된다.<br />다만 채도가 너무 높으면 피로감을 줄 수 있어<br />부드러운 톤으로 조정했다.
<img alt="" src="https://velog.velcdn.com/images/leeeydia/post/bd3e4993-5b58-46af-8f5d-2dc94633b64f/image.png" /></p>
<hr />
<h4 id="✔-sad-→-차분한-블루-톤">✔ SAD → 차분한 블루 톤</h4>
<p>파란색은 안정감과 신뢰를 상징하지만<br />동시에 우울한 감정과도 연결되는 색이다.</p>
<p>슬픔을 과하게 강조하지 않으면서도<br />차분한 분위기를 유지할 수 있도록<br />낮은 채도의 블루를 선택했다.
<img alt="" src="https://velog.velcdn.com/images/leeeydia/post/582d1648-fa56-4cff-be1a-96a59fa82f3e/image.png" /></p>
<hr />
<h4 id="✔-angry-→-톤-다운된-레드">✔ ANGRY → 톤 다운된 레드</h4>
<p>빨간색은 각성(arousal)을 높이는 색이다.<br />분노와 강하게 연결되는 색이지만<br />채도가 높을수록 긴장감을 더 유발할 수 있다.</p>
<p>일기 작성 공간은 감정을 폭발시키는 곳이 아니라<br />정리하는 공간이라고 생각했기 때문에<br />톤을 낮춘 레드 계열을 사용했다.</p>
<p><img alt="" src="https://velog.velcdn.com/images/leeeydia/post/ac8aa952-bb31-4208-91f3-e17f85fa606d/image.png" /></p>
<hr />
<h4 id="✔-calm-→-부드러운-그린-톤">✔ CALM → 부드러운 그린 톤</h4>
<p>초록색은 안정감, 균형, 회복(restoration)과 연결되는 색이다.<br />자연과 연관되기 때문에 심리적 안정에 긍정적인 영향을 준다는 연구도 존재한다.</p>
<p>CALM은 강한 감정보다는<br />균형 잡힌 상태, 숨을 고르는 상태에 가깝다고 생각했다.</p>
<p>그래서 자극적이지 않은<br />부드러운 그린 계열을 선택했다.</p>
<p><img alt="" src="https://velog.velcdn.com/images/leeeydia/post/9a15a7e0-bbb3-4af1-b97b-874942007bfc/image.png" /></p>
<hr />
<h3 id="💭-느낀-점">💭 느낀 점</h3>
<p>처음에는 단순히 “페이지 이동만 하면 되지”라고 생각했다.</p>
<p>하지만 감정이라는 데이터를 기반으로<br />UI가 달라지는 구조를 만들면서<br />단순한 화면 구현을 넘어<br />데이터 흐름과 사용자 경험을 설계하는 과정이라는 걸 깨달았다.</p>
<p>또한 색 선택에도 근거를 두려고 노력하면서<br />프론트엔드는 단순히 예쁘게 만드는 작업이 아니라<br />사용자의 감정을 고려하는 설계 작업이라는 점을 다시 느끼게 되었다.</p>
