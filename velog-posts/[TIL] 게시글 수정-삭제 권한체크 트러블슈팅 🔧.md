<p>오늘은 게시판 기능을 만들면서 좀 헷갈렸던 부분인
<code>게시글 수정/삭제를 작성자만 가능하게 하는 권한 체크</code> 부분을 정리해보기로 했다!</p>
<p>처음엔 &quot;if문 하나면 되는 거 아닌가?&quot; 라고 단순하게 생각했는데,
막상 구현해보니 나의 문제는 if문이 아니라 비교 대상(개념) 자체가 잘못되어 있었다. </p>
<h4 id="✅-중요-포인트-">✅ 중요 포인트 !</h4>
<p>권한 체크는 <code>비교</code>가 아니라 <code>데이터</code>가 필요하다.</p>
<p>권한 체크를 하려면, 게시글에 작성자 정보가 반드시 들어가야 한다.
게시글에 작성자 정보가 없다면</p>
<p>누가 썼는지도 알 수 없고 -&gt; 결국 비교도 할 수 없고 (if) -&gt; 작성자만 가능! 이라는 기능 자체가 성립하지 않는다.</p>
<h4 id="🔧-트러블-슈팅">🔧 트러블 슈팅</h4>
<p>처음 구현했을 때 이런 증상이 나왔다.</p>
<p>-&gt; 아무나 수정/삭제가 가능하다 !</p>
<p>원인은 <strong>비교 대상이 틀렸다.</strong></p>
<p>나는 게시글 id(글번호)와 로그인한 회원의 id(회원번호)를 비교하고 있었다. </p>
<p>해결방법은 간단했다 !</p>
<p>게시글에 작성자 정보를 저장하고, 그 값으로 비교하면 된다.</p>
<p>6주차 회고에 작성한 것 처럼 <code>요청 -&gt; 처리 -&gt; DB -&gt; 반환</code> 흐름을 제대로 이해 했다면 쉽게 풀었을 문제였다.</p>
<p>흐름을 다시 한번 체크해보면</p>
<pre><code>1️⃣ 요청 (Request)

사용자가

-게시글 수정

-게시글 삭제

를 요청한다

👉 이 시점엔 아직 누가 작성자인지 판단할 수 없음

2️⃣ 처리 (Service / 로직)

“이 요청을 허용해도 되는가?”

이걸 판단하려면 필요한 게 바로

현재 로그인한 사용자 id

게시글 작성자 id

그런데 ! 
게시글에 작성자 정보가 없으면
→ 이 단계에서 판단 자체가 불가능

3️⃣ DB

그래서 해결 방법은

글 작성 시점에

작성자ID 를 DB에 저장해 둔다

그러면 수정/삭제 요청이 왔을 때

DB에서 게시글을 조회

그 안에 작성자 ID 가 포함되어 있음

👉 이제 비교 가능

4️⃣ 반환 (Response)

작성자면 → 수정/삭제 성공

아니면 → “권한이 없습니다” 반환

이 결과가 사용자에게 전달됨</code></pre><p>이번 게시글 수정/삭제 권한체크 문제를 마주하며 
요청 시점에서 판단하려 하지 말고 처리에 필요한 데이터를 DB 단계에서 미리 저장해놓는 것이 중요하다는 걸 깨달았다.</p>
