<h3 id="로드-밸런싱">로드 밸런싱</h3>
<p>✅ 애플리케이션을 지원하는 리소스 풀에 들어오는 네트워크 트래픽(들어오는 요청)을 균등하게 분산하는 것을 말합니다.</p>
<p>✅ 애플리케이션 서버 앞단에 위치하며 클라이언트 요청을 지시하고 제어합니다.</p>
<p>✅ 애플리케이션의 가용성, 확장성, 보안 및 성능을 확보할 수 있습니다.</p>
<h3 id="로드-밸런싱-알고리즘">로드 밸런싱 알고리즘</h3>
<p> 로드 밸런서는 <strong>요청을 어떤 서버로 보낼지 결정하는 기준(알고리즘)</strong>을 가지고 있습니다.</p>
<h4 id="📖-라운드-로빈round-robin">📖 라운드 로빈(Round Robin)</h4>
<p>✅ 모든 요청을 순서대로 서버에 분배하는 방식입니다.</p>
<p>예를 들어 서버가 A, B, C 총 3대 존재한다면 요청은 다음과 같이 처리됩니다.</p>
<p>첫 번째 요청 → 서버 A</p>
<p>두 번째 요청 → 서버 B</p>
<p>세 번째 요청 → 서버 C</p>
<p>네 번째 요청 → 다시 서버 A</p>
<p>다섯 번째 요청 → 서버 B …</p>
<p>➡️ 서버 성능이 모두 비슷한 경우에 가장 간단하고 많이 사용되는 방식입니다.</p>
<h4 id="📖-가중치-라운드-로빈weighted-round-robin">📖 가중치 라운드 로빈(Weighted Round Robin)</h4>
<p>✅ 서버마다 처리 성능이 다를 때 사용하는 방식입니다.</p>
<p>예를 들어</p>
<p>서버 A : 성능 높음 (가중치 3)</p>
<p>서버 B : 보통 (가중치 2)</p>
<p>서버 C : 낮음 (가중치 1)</p>
<p>➡️ 요청이
A → A → A → B → B → C
와 같은 비율로 분배됩니다.</p>
<h4 id="📖-최소-연결-방식least-connections">📖 최소 연결 방식(Least Connections)</h4>
<p>✅ 현재 연결(처리 중인 요청)이 가장 적은 서버로 요청을 전달합니다.</p>
<p>➡️ 서버마다 처리 시간이 다를 때 효율적이며,
실시간 트래픽이 많은 서비스에서 자주 사용됩니다.</p>
<h4 id="📖-ip-해시-방식ip-hash">📖 IP 해시 방식(IP Hash)</h4>
<p>✅ 클라이언트의 IP 주소를 기준으로
항상 같은 서버로 요청을 보내는 방식입니다.</p>
<p>➡️ 로그인 유지, 세션 유지가 중요한 서비스에 적합합니다.</p>
