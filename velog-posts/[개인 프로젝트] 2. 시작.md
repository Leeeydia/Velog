<h3 id="📝-맛보기-git">📝 맛보기 Git</h3>
<p>이전 프로젝트를 진행하면서 깃 룰을 정한 다음 그에 맞게 커밋했는데
팀플 전에 개인프로젝트에서 한 번 연습하면 좋을 거 같아서 이번에 시도해보기로 다짐했다.</p>
<h4 id="개인-프로젝트용-git-룰-최소-기준">개인 프로젝트용 Git 룰 (최소 기준)</h4>
<p>혼자 진행하는 프로젝트이기 때문에<br />복잡한 규칙보다는 <strong>헷갈리지 않게 관리하는 것</strong>을 목표로 했다.</p>
<h4 id="브랜치">브랜치</h4>
<ul>
<li><code>main</code> : 최종 결과물</li>
<li><code>dev</code> : 개발용 브랜치</li>
</ul>
<blockquote>
<p>기능 작업은 <code>dev</code>에서 진행 후 <code>main</code>으로 병합</p>
</blockquote>
<hr />
<h4 id="커밋-규칙">커밋 규칙</h4>
<p>커밋 메시지는 아래 형식으로 작성한다.</p>
<ul>
<li><code>feat</code> : 기능 추가</li>
<li><code>fix</code> : 버그 수정</li>
<li><code>refactor</code> : 리팩토링</li>
<li><code>style</code> : 스타일 / UI 수정</li>
<li><code>docs</code> : 문서 수정</li>
<li><code>chore</code> : 설정 파일, 기타 작업</li>
</ul>
<p><strong>예시</strong></p>
<pre><code>feat: 회원가입 기능 추가
fix: 로그인 시 세션 오류 수정
docs: README 수정</code></pre><hr />
<h4 id="커밋-기준">커밋 기준</h4>
<ul>
<li>하나의 커밋에는 <strong>하나의 작업만</strong></li>
<li>작업 단위가 끝났을 때 커밋</li>
<li>의미 없는 커밋 메시지는 지양</li>
</ul>
<hr />
<h4 id="기타">기타</h4>
<ul>
<li>작업 시작 전 <code>git pull</code></li>
<li>큰 기능 작업 전에는 커밋 먼저 남기기</li>
<li>실험적인 코드는 바로 <code>main</code>에 반영하지 않기 (최최최최종 때 반영 !)</li>
</ul>
<hr />
<p>이 정도 룰만 지켜도<br />개인 프로젝트 관리에는 충분하다고 판단했다.</p>
